Endpoint-ы

EP wss://<host>/ws-native
STOMP 1.2

Чистый STOMP-over-WebSocket без SockJS. Для нативных мобильных клиентов (Android/iOS) и любых клиентов, у которых нет SockJS-обёртки. JWT передаётся в STOMP CONNECT-кадре в заголовке Authorization: Bearer <token>.

EP https://<host>/ws
STOMP 1.2 + SockJS

SockJS-fallback для веб-клиента (browser). Подключается через new SockJS('https://<host>/ws'). Внутри SockJS сам выбирает транспорт (WebSocket / XHR-streaming / XHR-polling). JWT — также в STOMP CONNECT-кадре.

Аутентификация (важно). JWT не передаётся в HTTP-заголовке WebSocket-handshake — Spring STOMP его всё равно не читает. JWT кладётся в STOMP CONNECT-кадр: 
CONNECT
accept-version:1.2
host:retailhub
Authorization:Bearer eyJhbGciOiJIUzUxMiJ9...

^@
Если JWT отсутствует или невалиден — соединение разрывается с STOMP ERROR-кадром. Анонимный CONNECT (без Authorization) разрешён только для клиентских QR-сессий: такой пользователь может подписаться только на /queue/request/{clientSessionToken}.

Авторизация SUBSCRIBE

SUBSCRIBE /topic/store/{storeId}/requests
MANAGER / ADMIN

Все обновления заявок магазина. Подписаться может только пользователь с ролью MANAGER или ADMIN, причём {storeId} в подписке должен совпадать с storeId в JWT. Любая попытка подписаться на чужой магазин или с ролью CONSULTANT возвращает STOMP ERROR.

ПараметрТипОписание
storeIdUUIDID магазина (берётся из JWT claim storeId)
SUBSCRIBE /topic/department/{departmentId}/requests
CONSULTANT

Заявки конкретного отдела. Подписаться может:

  • CONSULTANT — только если у него есть делегированная компетенция на этот отдел (запись в матрице user_departments); если консультант не работает в этом отделе — подписка отклоняется с STOMP ERROR.
  • MANAGER / ADMIN — на любой отдел своего магазина без ограничений.

Консультант, открывающий смену в нескольких отделах, должен сделать отдельный SUBSCRIBE на каждый отдел из своего списка компетенций.

ПараметрТипОписание
departmentIdUUIDID отдела из ответа GET /api/v1/auth/me (поле departments[].id)
SUBSCRIBE /queue/request/{clientSessionToken}
CLIENT (без JWT)

Статус конкретной заявки клиента. Подписывается клиент, отсканировавший QR. Авторизация — по знанию clientSessionToken (UUID, выдаётся в ответе POST /api/v1/requests). JWT для подписки не нужен.

ПараметрТипОписание
clientSessionTokenUUIDСессионная метка заявки

Типы событий

СобытиеКаналыОписание
REQUEST_CREATED store, department, client Клиент создал заявку через QR
REQUEST_WAITING store, department, client Заявка ждёт > 3 мин — повторное уведомление консультантам
REQUEST_ESCALATED store SLA нарушен (> 5 мин), эскалация на менеджера
REQUEST_ASSIGNED store, department, client Консультант взял заявку (отдел получает событие, чтобы остальные консультанты убрали её из списка ожидающих)
REQUEST_COMPLETED store, department, client Обслуживание завершено
REQUEST_CANCELED store, department, client Клиент отменил заявку
REQUEST_REASSIGNED store, department Клиент запросил смену консультанта
REQUEST_REMINDED — Клиент напомнил (только FCM push, не WebSocket)

Пример: Web (SockJS)

const sock = new SockJS('https://retailhub.example.com/ws');
const stomp = StompJs.Client.over(sock);

stomp.connectHeaders = { Authorization: 'Bearer ' + accessToken };
stomp.onConnect = () => {
    // Менеджер: все заявки магазина
    stomp.subscribe('/topic/store/' + storeId + '/requests', (msg) => {
        const upd = JSON.parse(msg.body);
        console.log('store:', upd.event_type, upd.status);
    });
};
stomp.activate();

Пример: Android / Kotlin (Krossbow / OkHttp)

val client = StompClient(OkHttpWebSocketClient())
val session = client.connect(
    url = "wss://retailhub.example.com/ws-native",
    customStompConnectHeaders = mapOf("Authorization" to "Bearer $accessToken")
)

// Консультант: подписки только на свои отделы (departmentIds из /api/v1/auth/me)
for (deptId in myDepartmentIds) {
    val sub = session.subscribeText("/topic/department/$deptId/requests")
    sub.collect { frame ->
        val update = json.decodeFromString<RequestUpdate>(frame)
        // ...
    }
}
Внимание для нативного клиента. Используй endpoint /ws-native, а не /ws. /ws требует SockJS-обёртку и для чистого WebSocket-клиента не работает (handshake пройдёт, но соединение закроется с PROTOCOL_ERROR сразу после CONNECT).
